\subsection{Połączenie z bazą danych}

W celu uproszczenia pracy z projektem zostało użyte rozwiązanie Atlas, czyli chmurowa baza danych MongoDB. MongoDB Atlas oferuje automatyczne skalowanie, kopie zapasowe oraz wbudowane mechanizmy bezpieczeństwa, co znacząco przyspiesza proces tworzenia aplikacji. Dzięki takiemu podejściu zespół mógł skupić się na implementacji logiki biznesowej, zamiast na administracji infrastrukturą bazodanową.

Konfiguracja połączenia wykorzystuje wzorzec asynchroniczny z obsługą błędów. Parametr \texttt{serverSelectionTimeoutMS} określa maksymalny czas oczekiwania na odpowiedź serwera bazy danych. Na listingu~\ref{lst:database_config} przedstawiono proces łączenia. Serwer łączy się z bazą danych za pomocą zmiennej środowiskowej \texttt{MONGODB\_URI}, co pozwala na łatwą zmianę środowiska bez modyfikacji kodu. Jeżeli połączenie nie nastąpi, wyświetlany jest typ błędu, a aplikacja kończy działanie z kodem błędu.

\begin{lstlisting}[style=javascript, caption = {Konfiguracja połączenia z bazą danych}, label = {lst:database_config}]
const connectDB = async () => {
  try {
    const conn = 
      await mongoose.connect( 
        process.env.MONGODB_URI, 
        { serverSelectionTimeoutMS: 5000, }
      );

    console.log(`MongoDB Connected: ${conn.connection.host}`);
    console.log(`Database: ${conn.connection.name}`);
  } catch (error) {
    console.error('MongoDB Connection Error:', error.message);
    process.exit(1);
  }
};
\end{lstlisting}


\subsection{Rejestracja użytkowników}
Aby w pełni korzystać z systemu aukcyjnego, użytkownicy muszą najpierw dokonać rejestracji. Użytkownik obowiązkowo podaje nazwę użytkownika, adres email, hasło, a opcjonalnie może podać imię, nazwisko oraz numer telefonu. Jeżeli użytkownik podał istniejący adres email bądź nazwę użytkownika, musi dokonać ich zmiany. Jeżeli wszystkie pola są wprowadzone prawidłowo, wtedy tworzony jest model User i token JWT oraz zapisywany jest użytkownik w bazie danych. Hasła są szyfrowane funkcją skrótu przed zapisem do bazy danych w celu zabezpieczenia użytkownika. Jeżeli wystąpi błąd podczas rejestracji, cały ten proces jest anulowany. Na listingu~\ref{lst:user_register} przedstawiono kod dotyczący rejestracji użytkowników.

\begin{lstlisting}[style=javascript, caption = {Implementacja procesu rejestracji użytkownika}, label = {lst:user_register}]
export const register = async (req, res) => {
  try {
    const {	username, email, password, 
    		firstName, lastName, phone } = req.body;
    if (!username || !email || !password) {
      return res.status(400).json({
        success: false,
        message: 'Podaj wymagane pola'
      });
    }
    const existingUser = 
      await User.findOne({ $or: [{ email }, { username }] });
    if (existingUser) {
      return res.status(400).json({
        success: false,
        message: existingUser.email === email
          ? 'Uzytkownik z tym adresem email juz istnieje'
          : 'Nazwa uzytkownika jest juz zajeta'
      });
    }
    const newUser = await User.create({
      username, email, password, firstName, lastName, phone
    });
    const verificationToken = newUser.createVerificationToken();
    await newUser.save({ validateBeforeSave: false });
    createSendToken(
      newUser, 201, res, 'Konto zostalo utworzone pomyslnie');  
  } catch (error) {
    if (error.code === 11000) {
      const field = Object.keys(error.keyPattern)[0];
      return res.status(400).json({
        success: false,
        message: `${field === 'email' ? 'Email' : 
        'Nazwa uzytkownika'} jest juz zajeta`
      });
    }    
    return sendErrorResponse(
      res, 500, 'Blad podczas rejestracji', error);
  }
};
\end{lstlisting}

\subsection{Logowanie użytkownika}
Po dokonaniu rejestracji, użytkownik może się zalogować do systemu aukcyjnego. Przy logowaniu wprowadza email bądź nazwę użytkownika oraz podane hasło podczas rejestracji.
Podczas procesu logowania porównujemy hashe hasła, które zostało wprowadzone przez użytkownika, z hashem zapisanym w bazie danych. Dzięki takiej praktyce podczas wycieku danych z bazy, użytkownicy nie tracą swojego loginu i hasła. Na listingu~\ref{lst:user_login} przedstawiono kod, który obsługuje logowanie użytkowników.

\begin{lstlisting}[style=javascript, caption = {Implementacja procesu logowania użytkownika}, label = {lst:user_login}]
export const login = async (req, res) => {
  try {
    const { credential, password } = req.body;

    if (!credential || !password) {
      return res.status(400).json({
        success: false,
        message: 'Podaj email/username i haslo'
      });
    }
    const user = await User.findByCredential(credential);
    if (!user || !(await user.comparePassword(password))) {
      return res.status(401).json({
        success: false,
        message: 'Nieprawidlowe dane logowania'
      });
    }
    if (!user.isActive) {
      return res.status(401).json({
        success: false,
        message: 'To konto zostalo dezaktywowane'
      });
    }
    createSendToken(user, 200, res, 'Zalogowano pomyslnie');
  } catch (error) {
    return sendErrorResponse(res, 500, 
    'Blad podczas logowania', error);
  }
};
\end{lstlisting}

\subsection{Autentykacja użytkownika}
Użytkownicy są autentykowani poprzez Json Web Token. Ten standard pozwala na bezpieczną wymianę danych pomiędzy klientem a serwerem jako obiekt JSON oraz na kontrolowanie sesji użytkowników.  JSON Web Token składa się z 3 części: nagłówka, ładunku oraz podpisu. Na listingu~\ref{lst:user_login} przedstawiono implementacje tokenów JWT.

\begin{lstlisting}[style=javascript, caption = {Implementacja autentykacji użytkownika}, label = {lst:user_auth}]
const signToken = (id) => {
  return jwt.sign({ id }, process.env.JWT_SECRET, {
    expiresIn: process.env.JWT_EXPIRES_IN || '7d'
  });
};

const createSendToken = 
	(user, statusCode, res, message = 'Sukces') => {
  
  const token = signToken(user._id);
  const cookieOptions = {
    expires: new Date(
      Date.now() + (process.env.JWT_COOKIE_EXPIRES_IN || 7) 
      				* 24 * 60 * 60 * 1000
    ),
    httpOnly: true,
  };

  res.cookie('jwt', token, cookieOptions);

  user.password = undefined;

  res.status(statusCode).json({
    success: true,
    message,
    token,
    data: { user }
  });
};
\end{lstlisting}

\subsection{Zarządzanie aukcjami}

\subsubsection{Stworzenie aukcji}

Zalogowany użytkownik może stworzyć wiele aukcji. Swojej aukcji nie może licytować, aby nie zawyżać sztucznie ceny. Przy utworzeniu każdej aukcji przez danego użytkownika, inkrementujemy liczbę wszystkich utworzonych aukcji. Na listingu~\ref{lst:auction_create} przedstawiono funkcje tworzącą aukcję.

\begin{lstlisting}[style=javascript, caption = {Obsługa utworzenia aukcji}, label = {lst:auction_create}]
export const createAuction = async (req, res) => {
  try {
    const auctionData = { ...req.body, seller: req.user._id };
    const startTime = 
      new Date(auctionData.startTime || Date.now());
    const endTime = new Date(auctionData.endTime);
    if (endTime <= startTime) {
      return res.status(400).json({
        success: false, 
        message: '...'
      });
    }
    const auction = await Auction.create(auctionData);
    await User.findByIdAndUpdate(req.user._id, {
      $inc: { 'stats.totalAuctionsCreated': 1 }
    });

    res.status(201).json({
      success: true, message: '...', data: auction
    });
  } catch (error) {
    if (error.name === 'ValidationError') {
      const messages = Object.values(error.errors)
      	.map(err => err.message);
      return res.status(400).json({
        success: false, message: messages[0]
      });
    }
    res.status(500).json({
      success: false, message: '...', error: error.message
    });
  }
};
\end{lstlisting}

\subsubsection{Licytowanie aukcji}
Użytkownik może licytować wiele aukcji na raz. Każda aukcja ma cene wywoławczą i najmniejszą cenę o jaką można podbić aukcje. Po utworzeniu zgodnego podbicia, aktualizujemy cene aukcji, poprzednie podbicia ustawiamy jako przebite i zatwierdzamy transakcję. Na listingu~\ref{lst:bidding} został przedstawiony proces licytowania aukcji przez jednego użytkownika.
\begin{lstlisting}[style=javascript, caption = {Proces licytowania aukcji}, label = {lst:bidding}]
export const placeBid = async (req, res) => {
  const mongoose = (await import('mongoose')).default;
  const session = await mongoose.startSession();
  session.startTransaction();

  try {
    const { amount } = req.body;
    const auctionId = req.params.id;
    const bidderId = req.user._id;

    const auction = await Auction.findById(auctionId)
    .session(session);

    const bidArray = await Bid.create([{
      auction: auctionId,
      bidder: bidderId,
      amount,
      previousBid: auction.currentPrice,
      isWinning: true,
      status: 'active'
    }], { session });
    
    const minimumBid = 
      auction.currentPrice + auction.bidIncrement;
    if (amount < minimumBid) {
      throw new Error(`Minimalna oferta to ${minimumBid} zl`);
    }
        
    const bid = bidArray[0];
    await Auction.findOneAndUpdate(
      { _id: auctionId, __v: auction.__v },
      {
        $set: {
          currentPrice: amount,
          winnerId: bidderId
        },
        $inc: {
          totalBids: 1,
          __v: 1
        }
      },
      { new: true, session, runValidators: true }
    );

    await Bid.updateMany(
      {
        auction: auctionId,
        _id: { $ne: bid._id },
        isWinning: true
      },
      {
        $set: {
          isWinning: false,
          status: 'outbid'
        }
      },
      { session }
    );

    await session.commitTransaction();

    const populatedBid = await Bid.findById(bid._id)
      .populate('bidder', 'username rating')
      .populate('auction', 'title currentPrice endTime');

    res.status(201).json({
      success: true,
      message: 'Oferta zostala zlozona pomyslnie',
      data: populatedBid
    });

  } catch (error) {
    await session.abortTransaction();
    res.status(500).json({
      success: false,
      message: error.message || 'Blad podczas skladania oferty'
    });
  } finally {
    session.endSession();
  }
};
\end{lstlisting}


\subsubsection{Wyświetlanie wszystkich aukcji}

Niezalogowani użytkownicy mogą wyświetlać wszystkie aukcje. Aukcje mogą być sortowane po kategorii, cenie albo po czasie aukcji. Na listingu~\ref{lst:all_auctions} przedstawiono funkcje, która pozwala na pobranie wszystkich aukcji.

\begin{lstlisting}[style=javascript, caption = {Obsługa mechanizmu wyświetlania wszystkich aukcji}, label = {lst:all_auctions}]
export const getAllAuctions = async (req, res) => {
  try {
    const {
      page = 1,
      limit = 20,
      category,
      minPrice,
      maxPrice,
      sortBy = 'endTime',
      sortOrder = 'asc',
      status = 'active'
    } = req.query;

    const query = {
      isDeleted: false
    };
    if (category) query.category = category;

    if (minPrice || maxPrice) {
      query.currentPrice = {};
      if (minPrice) 
        query.currentPrice.$gte = parseFloat(minPrice);
      if (maxPrice) 
        query.currentPrice.$lte = parseFloat(maxPrice);
    }

    if (status === 'active') {
      query.endTime = { $gt: Date.now() };
    }

    const skip = (parseInt(page) - 1) * parseInt(limit);

    const auctions = await Auction.find(query)
      .populate('seller', 'username rating')
      .populate('winnerId', 'username')
      .sort({ [sortBy]: sortOrder === 'desc' ? -1 : 1 })
      .limit(parseInt(limit))
      .skip(skip);

    const total = await Auction.countDocuments(query);

    res.status(200).json({
      success: true,
      results: auctions.length,
      totalPages: Math.ceil(total / parseInt(limit)),
      currentPage: parseInt(page),
      total,
      data: auctions
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: 'Blad podczas pobierania aukcji',
      error: error.message
    });}};
\end{lstlisting}
