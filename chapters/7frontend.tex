\section{Implementacja warstwy interfejsu użytkownika serwisu aukcyjnego}

\subsection{Rola warstwy interfejsu użytkownika w systemie aukcyjnym}

Struktura części klienckiej odpowiedzialna jest za interakcję użytkownika z systemem aukcyjnym. Jej głównym zadaniem jest przedstawienie danych dostarczanych przez strukturę części serwerowej. Istotnym aspektem jest, aby interfejs użytkownika zapewniał odpowiednią użyteczność oraz spójny interfejs, poprzez przejrzyste układy stron. Ze względu na dążenie do większej przejrzystości interfejsu oraz ujednolicenia wyglądu aplikacji, w trakcie implementacji zmieniono wygląd niektórych widoków w stosunku do projektu przedstawionego w rozdziale~\ref{sec:projekt}.

\subsection{Struktura części interfejsu użytkownika}

Na rysunku~\ref{fig:frontend} przedstawiono strukturę części odpowiedzialnej za interfejs użytkownika:

\begin{itemize}
  \item public - w tym folderze zawarte są pliki statyczne oraz zasoby 3D, wykorzystywane w aplikacji do renderowania obiektów.
  \item src/components - w tym folderze zadeklarowane są komponenty wielokrotnego użytku takie jak: Navbar, Footer, AuctionCard.
  \item src/contexts - w tym folderze znajdują się konteksty React, które są odpowiedzialne za zarządzanie stanem autoryzacji użytkownika.
  \item src/pages - w tym folderze zawarte są wszystkie widoki w aplikacji widoczne dla użytkownika.
  \item	src/services - w tym folderze opisana jest komunikacja części interfejsu użytkownika z częścią serwerową.
  \item src/styles - w tym folderze znajdują się pliki stylów CSS aplikacji.
  \item src/utils - w tym folderze opisane są funkcje pomocnicze.
\end{itemize}

Dzięki temu rozwiązaniu usprawniono działanie aplikacji, poprawiając komfort użytkowania.

\subsection{Komunikacja części klienckiej z częścią serwerową}
Warstwa interfejsu użytkownika serwisu aukcyjnego komunikuje się z częścią serwerową za pomocą interfejsu API opartego na protokole HTTP~\cite{http}. Wymiana danych realizowana jest asynchronicznie przy wykorzystaniu metody \texttt{fetch}. W celu uporządkowania komunikacji z częścią serwerową zastosowano wydzieloną warstwę serwisów, odpowiedzialną za realizację zapytań sieciowych. Przykład tego zastosowania przedstawiono na listingu~\ref{lst:apijs}.

\begin{lstlisting}[style=javascript, caption = {Zawartośc pliku api.js}, label = {lst:apijs}]
import { handleResponse, getAuthHeaders } 
from '../utils/apiHelpers';

const API_URL = import.meta.env.VITE_API_URL 
|| 'http://localhost:8080/api';

// Auth API calls

export const authAPI = {
  register: async (userData) => {
    const response = await fetch(`${API_URL}/users/register`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify(userData),
    });
   
    return handleResponse(response);
  },

  login: async (credential, password) => {
    const response = await fetch(`${API_URL}/users/login`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({ credential, password }),
    });
    
    return handleResponse(response);
  }
};

//...
\end{lstlisting}

\subsection{Walidacja danych}

Walidacja danych została zaimplementowana zarówno w części interfejsu użytkownika, jak i w części serwerowej, w celu weryfikacji wartości wprowadzanych przez użytkowników. Dzięki tej praktyce możliwe jest zapobieganie przesyłaniu niepoprawnych danych do serwera oraz informowanie użytkownika o błędach w czasie rzeczywistym. Na listingu~\ref{lst:validation} przedstawiono przykład walidacji formularza rejestracyjnego, obejmującej sprawdzenie nazwy użytkownika, poprawności adresu email oraz wymagań dotyczących hasła.

\begin{lstlisting}[style=javascript, caption = {Walidacja danych po stronie interfejsu użytkownika}, label = {lst:validation}]
  const validateForm = () => {
    if (!formData.username) {
      setError('Nazwa uzytkownika jest wymagana');
      return false;
    }
    if (!/^[a-zA-Z0-9]+$/.test(formData.username)) {
      setError('Nazwa moze zawierac tylko litery, cyfry.');
      return false;
    }

    if (!formData.email) {
      setError('Email jest wymagany');
      return false;
    }
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(formData.email)) {
      setError('Podaj prawidlowy adres email');
      return false;
    }

    if (!formData.password) {
      setError('Haslo jest wymagane');
      return false;
    }
    if (formData.password.length < 8) {
      setError('Haslo musi mieć co najmniej 8 znakow');
      return false;
    }
    if (formData.password !== formData.passwordConfirm) {
      setError('Hasla nie sa identyczne');
      return false;
    }
  };
\end{lstlisting}

\subsection{Obsługa błędów}

W części interfejsu użytkownika zaimplementowano mechanizmy obsługi błędów, które zapewniają stabilność działania systemu oraz przekazywanie czytelnych informacji podczas wyświetlania błędów aplikacji.

W przypadku formularza rejestracyjnego zastosowano asynchroniczną funkcję, która obsługuje zdarzenie wysyłane do formularza. Funkcja kontroluje poprawność danych wejściowych, po czym zarządza stanem ładowania i reaguje na błędy, jeżeli takowe powstaną. Implementacja tej części jest przedstawiona na listingu~\ref{lst:error_handle}.

\begin{lstlisting}[style=javascript, caption = {Obsługiwanie błędów po stronie interfejsu użytkownika}, label = {lst:error_handle}]
  const handleSubmit = async (e) => {
    e.preventDefault();
    setError('');

    if (!validateForm()) {
      return;
    }
    setLoading(true);
    try {
      const { passwordConfirm, ...userData } = formData;
      const result = await register(userData);
      if (result.success) {
        navigate('/');
      } else {
        setError(result.message || 'Blad rejestracji');
      }
    } catch (err) {
      setError('Wystapil blad podczas rejestracji. ');
    } finally {
      setLoading(false);
    }
  };
\end{lstlisting}
